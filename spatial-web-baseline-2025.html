STD-2 · Modeling Language
Hyperspace Modeling Language (HSML)
SWF STD-2:2025 (0.2.0) — a core compliance target of IEEE 2874. HSML defines a human- and machine-readable semantic modeling language and ontology for the Spatial Web, with a shared vocabulary for Entities, Domains, Agents, Activities, Credentials, Channels, Hyperspaces, and Governance. The Hyperspace Module supports topological, metric, vector, cellular, graph, and datatype spaces, expressed using points, paths, subspaces, tensor products, and functors. Built on RDF 1.1/1.2, RDF-star, OWL 2, SHACL, and JSON-LD 1.1, with HSQL (a SPARQL 1.2-aligned query language) for reasoning over hyperspace relations.
STD-3 · Transaction Protocol
Hyperspace Transaction Protocol (HSTP)
SWF STD-3:2025 (0.1.0) — Implementation specification for HSTP, mapping the IEEE 2874 reference model into concrete clauses developers can build and test against. Defines symmetric messaging, payload encryption, OPERATIONs, core data structures, and protocol bindings (HTTP/2, MQTT). Serves as the basis for HSTP conformance testing.
STD-4 · Identifiers
Spatial Web Identifiers (SWIDs) & SWID Documents
SWF STD-4:2025 (0.1.0) — Defines SWIDs and SWID Documents based on W3C DID Core. All Spatial Web Entities (including Credentials) carry SWIDs; the Spatial Web SWID Registry ensures uniqueness, while most SWIDs are created by a DID Issuer on behalf of the Entity and need not be recorded in any centralized registry.
STD-5 · DID Method
did:swid Method
SWF STD-5:2025 (0.1.0) — Defines did:swid, the DID method for the Spatial Web. Specifies Create/Read/Update/Deactivate operations against the Spatial Web SWID Registry, the registry role under a Designated Authority, and security & privacy considerations.
STD-6 · Universal Domain Graph
UDG Design Specification, v0.1 Ready for technical review
SWF STD-6:2025 (0.1) — The Universal Domain Graph as a medium for collective intelligence in the Spatial Web. Treats UDG as a knowledge graph in which DOMAINS are the primary entity, as a hyperspace with spatially-embedded entities, and as a network of registries with hierarchical domain governance. Derives component requirements that flow back into the Spatial Web engineering effort.
Agent Framework
STD-7 Spatial Web Agent Framework Implementation Specification Draft
Agent Framework working draft, is under development including a Universal Agent Model contributing the foundational treatment of agency.
STD-8 · Governance
Spatial Web Governance Recommended Practice In Development
Governance Recommended Practice is under development including policies and procedures for managing the Domain Registry and the UDG.

Roadmap Ahead

What Needs to Be Done

From Critical Design through Initial Operating Capability and into continuous operation — the remaining work to take the Spatial Web from a designed system to an operational one.

Critical Design
Next Phase
Definition of Done
Critical Design Baseline
A critical design baseline is achieved once:
  • all design component designs are initially complete,
  • the expanded set of Spatial Web components is in scope, and
  • multiple prototypes demonstrate the designs.
Milestone Review
Critical Design Review (CDR)
Establishes the plan for Initial Operating Capability (IOC).
Initial Operating Capability
Planned
  • Deployment of all components needed for IOC.
  • Interoperability testing across reference implementations.
  • Pilot demonstrations of application scenarios.
Continuous Operations
Future
Sustained operation, evolution, and governance of the deployed Spatial Web following IOC — including standards maintenance, conformance, and ecosystem support.
